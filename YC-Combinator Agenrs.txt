Yes. What you're describing is a very realistic **agentic job/outreach system**, and YC is a particularly good starting data source because its directory exposes company, batch, status, founders, jobs, and other company information. YC also explicitly promotes its platform as a way to connect candidates with founders and startup jobs. ([Y Combinator][1])

The important distinction is that I would **not build the final version as a bot that automatically logs into LinkedIn and sends hundreds of messages**. LinkedIn explicitly prohibits unauthorized automated activity, including bots that scrape data or send/redirect messages. ([LinkedIn][2])

Instead, build this:

## Your system

```text
                    ┌──────────────────────┐
                    │   Scheduler / Trigger │
                    └──────────┬───────────┘
                               ↓
                    ┌──────────────────────┐
                    │  YC Startup Discovery │
                    │       Agent           │
                    └──────────┬───────────┘
                               ↓
              ┌─────────────────────────────────┐
              │ New / Relevant Startup Database │
              └────────────────┬────────────────┘
                               ↓
                    ┌──────────────────────┐
                    │ Founder Research      │
                    │ Agent                 │
                    └──────────┬───────────┘
                               ↓
             ┌──────────────────────────────────┐
             │ Founder + LinkedIn + Company     │
             │ + Website + Jobs + Batch + etc.  │
             └────────────────┬─────────────────┘
                              ↓
                    ┌──────────────────────┐
                    │ Fit / Qualification   │
                    │ Agent                 │
                    └──────────┬───────────┘
                               ↓
                    ┌──────────────────────┐
                    │ Personalization       │
                    │ / Research Agent      │
                    └──────────┬───────────┘
                               ↓
                    ┌──────────────────────┐
                    │ Message Generation    │
                    │ Agent                 │
                    └──────────┬───────────┘
                               ↓
                    ┌──────────────────────┐
                    │ HUMAN APPROVAL        │
                    │       YOU             │
                    └──────────┬───────────┘
                               ↓
                    ┌──────────────────────┐
                    │ LinkedIn / YC / Email │
                    │ Manual Send           │
                    └──────────┬───────────┘

                    ┌──────────────────────┐
                    │ Outreach Tracker      │
                    └──────────────────────┘
```

### 1. YC Discovery Agent

This agent periodically checks YC's public directory.

For example, it could be instructed:

> Find newly added active YC startups from the current and previous batch. Extract company name, YC batch, industry, location, founders, founder roles, company description, website and available jobs.

YC company pages currently expose information such as batch, active status, team size, location and named founders. For example, current Fall 2026 pages show exactly this structure. ([Y Combinator][3])

Your database could therefore have:

```text
startup_id
company_name
yc_batch
status
industry
location
company_description
website
founder_name
founder_role
founder_yc_url
linkedin_url
jobs_url
discovered_at
```

---

### 2. Founder Research Agent

This is where the system becomes much more interesting.

Suppose YC returns:

```text
Company: Kailash Labs
Batch: F26
Founder: XYZ
Role: Founder/CEO
Website: kailashlabs.com
```

The agent researches **public professional information** to find:

```text
Founder
    ↓
LinkedIn profile URL
    ↓
Current role
    ↓
Previous companies
    ↓
Technical/product interests
    ↓
Company's current product
    ↓
Recently announced hiring
    ↓
Possible relevance to your profile
```

YC itself sometimes provides external founder information, and its founder-verification system can expose a founder's LinkedIn URL when that founder has chosen to make it available. ([Y Combinator][4])

So your agent shouldn't assume:

> "Search LinkedIn until you find this person."

Instead:

> "Find a publicly available professional profile that can be confidently matched to this YC founder."

That prevents mistaken identity.

# 4. Fit Agent

This agent answers:

> "Is this startup actually relevant to Raj?"

For example:

```text
Startup:
AI-native product analytics platform

Founder:
Building an agentic analytics product

Candidate:
SQL + Power BI + Python + GenAI + Product Analytics

Fit:
HIGH
```

Whereas:

```text
Startup:
Biotech drug discovery

Candidate:
Business/Data/Product Analytics

Fit:
LOW
```

You shouldn't ask the LLM simply to generate a message for everybody.

First ask it:

```text
Should we contact this founder?
Why?
What evidence supports the match?
What could Raj contribute?
```

That dramatically improves the quality.

---

# 5. Founder Research Agent

Now the agent researches the **specific founder**, rather than just the startup.

For example it might find:

```text
Founder:
A

Company:
AI infrastructure startup

Founder background:
Previously ML engineer

Current company:
Building X

Recent activity:
Hiring first product/data employees

Potential connection:
Raj has experience with data analytics + GenAI + agentic systems.
```

Now the message can be genuinely personalized.

# 6. Message Agent

This is where your predefined message template becomes the **policy**, rather than allowing the LLM to freestyle.

You could give it something like:

```text
Core message:

I'm genuinely interested in what you're building.
I'm currently working in [area].
I have experience with [relevant experience].
I've been building [relevant projects].
I'd love to explore whether I could contribute to what you're building.
```

The LLM's job is then:

```text
YOUR CORE MESSAGE
        +
FOUNDER CONTEXT
        +
COMPANY CONTEXT
        +
YOUR RELEVANT EXPERIENCE
        ↓
PERSONALIZED MESSAGE
```

For example, instead of sending the same:

> I'm curious to work with you...

to 100 founders, it could produce something like:

> I've been following what you're building around agentic data infrastructure, and it overlaps heavily with the kind of AI/data systems I've been working on...

The personalization should be grounded in information the agent actually found, not invented.

# 8. Outreach Memory

Your system should remember everything.

For example:

```text
Founder          Status
────────────────────────────────
John Smith       Sent
Sarah Chen       Accepted
Michael Lee      No response
David Kumar      Rejected
Alex Brown       Follow-up due
```

And critically:

```text
NEVER CONTACT AGAIN
```

The agent checks this before generating anything.

That prevents the embarrassing situation of accidentally messaging the same founder twice.

# The really interesting part

You don't necessarily need LinkedIn as your primary communication channel.

YC itself currently has a candidate system where you can create a profile, apply to startup jobs, and allow founders to contact you. YC says candidates can apply to thousands of startup jobs with one profile and let YC founders contact them. ([Y Combinator][1])

So your agent can actually have **three possible outreach routes**:

```text
                   Founder identified
                          │
              ┌───────────┼───────────┐
              ↓           ↓           ↓
          YC Job        LinkedIn     Email
          Apply         Profile      Public
              │           │           │
              └───────────┼───────────┘
                          ↓
                  Human approval
```

That is substantially more useful than a "LinkedIn spam bot."

```text
 YC Discovery      Founder Research    Job Research
     Agent              Agent              Agent
       │                 │                 │

                         ↓
                   Qualification
                       Agent
                         ↓
                  Profile Matching
                       Agent
                         ↓
                  Personalization
                       Agent
                         ↓
                  Message Writer
                       Agent
```

Notice something important:

**You don't need 10 independent LLMs.**

You wake up and open:

```text
   YC: F26
   Match: 87%

   [Review Message]

3. ...
```

You spend perhaps a few minutes reviewing the generated opportunities rather than manually doing:

**YC → startup → founder → LinkedIn → research → write → send**

for every startup.

And there is an important architectural lesson here:

**The LLM isn't the system.**

The LLM is the reasoning layer inside a larger system:

```text
Data sources
     ↓
Tools
     ↓
Agents
     ↓
Memory/database
     ↓
Reasoning
     ↓
Human approval
     ↓
Action
```

That is a genuinely good **agentic AI portfolio project** because it demonstrates tool calling, structured outputs, web research, RAG/profile retrieval, agent orchestration, memory, evaluation, and human-in-the-loop—not merely "I asked an LLM to write LinkedIn messages."

YC also already has an interesting precedent: some YC companies themselves are building AI systems for recruiting/outbound, which reinforces that the workflow you are imagining is technically meaningful. ([Y Combinator][6])

The next sensible step is to design **V1 of this system as an actual Function/Tool Contract**, starting with exactly how the **YC Discovery Agent gets a startup → returns structured JSON → passes it to the Founder Research Agent**. That connects very directly to the JSON/Python/LLM architecture you were asking about recently.
